ARCHITECTURE OVERVIEW
----------------------
  [User Browser]
       |
       v
  [Render Web Service]     <-- FastAPI (main.py) + serves index.html
       |
       |--- SQL queries ---> [AWS RDS PostgreSQL (t3.micro)]
       |--- Celery tasks ---> [AWS EC2 t2.micro]
                                  |-- Celery Worker (task.py)
                                  |-- Redis (local, same box)

WHY THIS SPLIT:
  - EC2 is required for the Celery worker because task.py uses
    resource.setrlimit(), which is a Linux-only kernel syscall.
    It will not work on Render or Windows.
  - RDS gives you managed PostgreSQL with automated backups and
    a free tier for 12 months (750 hrs/month on t3.micro).
  - Render handles the FastAPI web server cleanly with auto-deploys
    from GitHub, free HTTPS, and no server management needed.

================================================================================
  STEP 1 — PREPARE YOUR CODE (do this first, locally)
================================================================================

1.1  Create a render.yaml in your project root (for Render auto-deploy):
---------------------------------------------------------------------
     Create file: render.yaml

     services:
       - type: web
         name: codebattle-api
         runtime: python
         buildCommand: pip install -r requirements.txt
         startCommand: uvicorn app.main:app --host 0.0.0.0 --port $PORT
         envVars:
           - key: DATABASE_URL
             sync: false
           - key: REDIS_URL
             sync: false
           - key: SECRET_KEY
             sync: false

1.2  Create a separate docker-compose for EC2 (worker only):
---------------------------------------------------------------------
     Create file: docker-compose.worker.yml

     version: "3.9"
     services:
       redis:
         image: redis:7-alpine
         restart: always
         command: redis-server --appendonly yes
         ports:
           - "6379:6379"

       worker:
         build: .
         command: celery -A app.worker.task:cel worker --loglevel=info
         restart: always
         depends_on:
           - redis
         env_file: .env

1.3  Update your Dockerfile start command:
---------------------------------------------------------------------
     In your Dockerfile, change the CMD line to:

     CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]

     (Remove --reload for production. It causes issues on Render.)

1.4  Push everything to GitHub:
---------------------------------------------------------------------
     git add .
     git commit -m "Add render.yaml and worker docker-compose"
     git push origin main

================================================================================
  STEP 2 — AWS RDS (PostgreSQL Database)
================================================================================

TIME NEEDED: ~15 minutes
URL: https://console.aws.amazon.com/rds

--- CREATING THE DATABASE ---

2.1  Log into AWS Console → Search "RDS" → Click "Create database"

2.2  Choose these settings EXACTLY:
       - Creation method:      Standard create
       - Engine type:          PostgreSQL
       - Engine version:       PostgreSQL 15.x (latest 15)
       - Template:             FREE TIER  <-- CRITICAL, pick this
       - DB instance ID:       codebattle-db
       - Master username:      postgres
       - Master password:      [make a strong password, save it]
       - DB instance class:    db.t3.micro  (should be pre-selected)
       - Storage type:         gp2
       - Allocated storage:    20 GB
       - Storage autoscaling:  DISABLE THIS (keeps you free tier)

2.3  Connectivity settings:
       - VPC:                  Default VPC
       - Public access:        YES  <-- needed so Render can connect
       - VPC security group:   Create new → name it "codebattle-rds-sg"
       - Availability zone:    No preference
       - Database port:        5432

2.4  Additional configuration:
       - Initial database name: codebattle
       - Automated backups:    Enable (7 days, free)
       - Encryption:           Enable

2.5  Click "Create database" → wait 5-10 minutes for it to spin up.

--- GETTING YOUR CONNECTION STRING ---

2.6  Once status is "Available", click the database name.
     Find the "Endpoint" under "Connectivity & security". It looks like:
       codebattle-db.xxxxxxxxxx.us-east-1.rds.amazonaws.com

2.7  Your DATABASE_URL will be:
       postgresql://postgres:[PASSWORD]@[ENDPOINT]:5432/codebattle

     Example:
       postgresql://postgres:mypassword123@codebattle-db.abc123.us-east-1.rds.amazonaws.com:5432/codebattle

     SAVE THIS. You will need it in Steps 3 and 4.

--- OPENING THE FIREWALL ---

2.8  Go to EC2 → Security Groups → find "codebattle-rds-sg"
     Click "Edit inbound rules" → Add rule:
       Type:       PostgreSQL
       Port:       5432
       Source:     0.0.0.0/0   (allows all — you'll tighten this later)

     NOTE: After setup you should restrict the source to only your
     EC2's IP and Render's IP range for security. For now 0.0.0.0/0
     gets everything working.

================================================================================
  STEP 3 — AWS EC2 (Celery Worker + Redis)
================================================================================

TIME NEEDED: ~20 minutes
URL: https://console.aws.amazon.com/ec2

--- LAUNCHING THE INSTANCE ---

3.1  Go to EC2 → Click "Launch instance"

3.2  Settings:
       - Name:                 codebattle-worker
       - AMI:                  Ubuntu Server 24.04 LTS (Free tier eligible)
       - Instance type:        t2.micro  <-- FREE TIER
       - Key pair:             Create new key pair
                               Name: codebattle-key
                               Type: RSA
                               Format: .pem
                               >> Download and SAVE this .pem file.
                                  You cannot download it again.
       - Network settings:     Allow SSH from My IP
       - Storage:              8 GB gp2 (default, free tier)

3.3  Click "Launch instance" → wait 2-3 minutes.

--- CONNECTING TO YOUR EC2 INSTANCE ---

3.4  Find your EC2 instance → note the "Public IPv4 address"
     (looks like: 54.123.45.67) — SAVE THIS.

3.5  Open a terminal on your local machine:

     Windows (PowerShell):
       icacls "C:\path\to\codebattle-key.pem" /inheritance:r /grant:r "%USERNAME%:R"
       ssh -i "C:\path\to\codebattle-key.pem" ubuntu@[EC2_PUBLIC_IP]

     Mac/Linux:
       chmod 400 ~/Downloads/codebattle-key.pem
       ssh -i ~/Downloads/codebattle-key.pem ubuntu@[EC2_PUBLIC_IP]

--- INSTALLING DOCKER ON EC2 ---

3.6  Once SSHed in, run these commands one by one:

     sudo apt-get update
     sudo apt-get install -y ca-certificates curl
     sudo install -m 0755 -d /etc/apt/keyrings
     sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
     sudo chmod a+r /etc/apt/keyrings/docker.asc
     echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
     sudo apt-get update
     sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
     sudo usermod -aG docker ubuntu
     newgrp docker

3.7  Verify Docker works:
     docker --version
     docker compose version

--- DEPLOYING YOUR WORKER ON EC2 ---

3.8  Clone your GitHub repo onto EC2:
     git clone https://github.com/[YOUR_USERNAME]/[YOUR_REPO].git
     cd [YOUR_REPO_NAME]

3.9  Create your .env file on EC2:
     nano .env

     Paste this (replace values with yours):
     ---
     DATABASE_URL=postgresql://postgres:[PASSWORD]@[RDS_ENDPOINT]:5432/codebattle
     REDIS_URL=redis://redis:6379/0
     SECRET_KEY=[any long random string, e.g. run: openssl rand -hex 32]
     ---
     Press Ctrl+X, then Y, then Enter to save.

3.10 Start the worker:
     docker compose -f docker-compose.worker.yml up -d --build

3.11 Verify it's running:
     docker compose -f docker-compose.worker.yml ps
     docker compose -f docker-compose.worker.yml logs worker

     You should see: "celery@... ready."

--- OPEN EC2 SECURITY GROUP PORTS ---

3.12 Go to AWS Console → EC2 → Security Groups
     Find the security group for your EC2 instance.
     Click "Edit inbound rules" → Add rule:
       Type:     Custom TCP
       Port:     6379
       Source:   0.0.0.0/0

     (This lets Render's FastAPI connect to Redis on this EC2.)

     NOTE: Your EC2's Redis will be accessible at:
       redis://[EC2_PUBLIC_IP]:6379/0

--- RUN DATABASE MIGRATIONS ---

3.13 While still SSHed into EC2, run migrations so RDS tables are created:
     docker compose -f docker-compose.worker.yml run --rm worker alembic upgrade head

     Or if alembic isn't set up, the FastAPI startup event will create tables
     automatically when Render deploys (via create_tables() in main.py).

================================================================================
  TROUBLESHOOTING
================================================================================

PROBLEM: Render deploys but API crashes on startup
  CHECK: Go to Render dashboard → your service → "Logs"
  LIKELY CAUSE: DATABASE_URL is wrong. Make sure it starts with
                "postgresql://" not "postgres://" (SQLAlchemy requirement).
  FIX: Change "postgres://" to "postgresql://" in your DATABASE_URL env var.

PROBLEM: Celery worker logs show "redis.exceptions.ConnectionError"
  CHECK: docker compose -f docker-compose.worker.yml logs worker
  LIKELY CAUSE: REDIS_URL in EC2 .env is wrong.
                Inside docker-compose, Redis hostname is "redis" (the service name).
                So REDIS_URL=redis://redis:6379/0 is correct for the worker.
  NOTE: Render's FastAPI needs REDIS_URL=redis://[EC2_PUBLIC_IP]:6379/0
        EC2's worker needs REDIS_URL=redis://redis:6379/0
        These are DIFFERENT. EC2 .env uses the docker service name.
        Render env var uses the public IP.

PROBLEM: Submissions are received but verdict stays "pending" forever
  CHECK: Worker is not running or not connected to same Redis/DB.
  FIX:  SSH into EC2 → docker compose -f docker-compose.worker.yml logs worker
        Look for connection errors.

PROBLEM: RDS connection refused
  LIKELY CAUSE: Security group not allowing inbound on port 5432.
  FIX: Re-check Step 2.8 — make sure 5432 is open in RDS security group.

PROBLEM: resource.setrlimit ImportError or not working
  This is EXPECTED if the worker runs anywhere other than Linux (EC2).
  This is why we run the Celery worker on EC2 specifically.
  Do NOT move the worker to Render — it won't work.

PROBLEM: Free tier on Render — API goes to sleep after 15 minutes of inactivity
  On Render's free tier, services spin down after inactivity.
  The first request after sleep takes ~30 seconds to wake up.
  OPTIONS:
    a) Upgrade to Render's $7/month "Starter" plan (no sleep).
    b) Use a free uptime monitor (e.g. UptimeRobot) to ping your API
       every 14 minutes to keep it awake.
       URL to ping: https://codebattle-api.onrender.com/
